# 타 지사 전환(Multi-Branch Migration) 기술 검토 및 설계 가이드

> 본 문서는 현재 **한국도로공사 고령지사(고속국도 제12호선 광주대구선 · 함양IC `95.0k` ~ 옥포JC `176.0k`)** 기준으로 최적화된 `bionda` 시스템을 향후 **다른 지사(단일 노선 또는 복수 노선 관할 지사)**로 전환·확장할 때 필요한 데이터 선정 절차, 코드베이스 내 수정 지점, 그리고 권장 설정 분리 아키텍처를 정리한 영구 기술 기준서입니다.

---

## 1. 지사 전환 시 준비해야 할 6대 핵심 데이터 체크리스트

새 지사로 전환할 때는 개발 착수 전에 아래 6가지 현장·공공 API 기준 정보를 먼저 확정해야 합니다.

| 순서 | 항목 | 확인 원천 (공공 API / 현장 자료) | 현행 고령지사 예시 | 전환 시 핵심 점검 포인트 |
|:---:|---|---|---|---|
| **1** | **관할 노선 및 이정 범위** | 도로공사 지사 관할도 (본선 + 지선 여부, 기점·종점 `km`) | 광주대구선(`012`) 본선 단일<br>`함양IC(95.0k) ~ 옥포JC(176.0k)` + 선행 `남원(50.0k~)` | **2개 이상 노선**(예: 본선+지선, JC 교차노선) 관할 지사는 노선 배열(`routes[]`) 구조로 정의 필요 |
| **2** | **단기·초단기예보 행정구역 (약 10~15개소)** | 기상청 날씨누리 동네예보 (`weather.go.kr/w/rest/zone/dong.do`) 읍·면·동 대표 위경도 | 함양읍·지곡면·수동면·거창읍·남상면·남하면·가조면·가야면·야로면·쌍림면·대가야읍·성산면·옥포읍 (`13개소`, 고유 `12격자`) | Cloudflare Workers 동시 연결(6개)·서브요청(50개) 한도 준수를 위해 **고유 DFS 격자(`nx, ny`) 기준 10~15개 이내** 권장 (인접 면은 격자 자동 공유) |
| **3** | **기상특보 감시 지점 및 세부 특보구역 (8개소)** | 기상청 `wrn_now_data.php` 특보구역코드 + CAP XML 폴리곤 (`kma-cap`) | `함양중부`, `거창군남부`, `합천군서북부`, `고령군`, `대구 달성군남부` + 선행 `남원` 등 `8개소` | 시·군 단위 외에 **`OO산지`·`OO평지`·`OO남부/서북부` 등 세부 특보구역 폴리곤**과 매칭되는 좌표인지 반드시 검증 + **편서풍 상류 선행 지점 1~2곳** 포함 권장 |
| **4** | **기상청 3종 도로기상 코드 매핑 (관측소 · 위험ZIP · RWIS 콘존)** | ① 도로관측 `road_stn_obs.php` (`var` 노선코드, `stnId`)<br>② 위험ZIP `road_file_down.php` (`roadNum` 3자리)<br>③ RWIS `rwis.kma.go.kr` (`0120CZE...` 콘존 ID) | ① `var=14` (`14206` 함양 ~ `14410` 논공교 7개소 + 선행 4개소)<br>② `roadNum=012`<br>③ `0120CZE/S` `160~230` (8개 구간) | **가장 주의할 지점**: 고속국도 번호(`12호선`)와 기상청 도로관측 노선코드(`var=14`)는 번호 체계가 다름! 노선별 KMA `var` 번호 사전 대조 필수 |
| **5** | **RWIS 구간별 연계 CCTV 선정** | 국토부 ITS Open API(`openapi.its.go.kr:9443/cctvInfo` 경위도 범위) + 로드플러스 `cctvId` | `127.25~128.65°E, 35.3~35.9°N` 내 본선 62개 지점(123대 카메라) + 주요 거점 19개소 | **결빙취약교량 · 터널 갱구 · 고개 정상 · IC/JC** 우선 매칭. CCTV가 없는 단거리 콘존(예: `1.5km` 미만 JC 구간)은 인접 구간 CCTV를 `nearZones`로 연결 |
| **6** | **노선 미니맵(`index`) 및 RWIS 상황실 지도(`rwis`) 도형·배치** | 통계청 시·도/시·군 경계(`southkorea-maps`) + 노선 중심선 좌표열(`km, lat, lon`) | `public/route12.js`, `public/minimap.js`, `public/rwis-data.js` (`RWIS_ROUTE_GEO`, `dock`, `dx/dy`) | **남↔북 종단 노선**(경부·중부내륙·서해안·중앙선 등)은 가로형(`1600×700`) 캔버스에 맞도록 **주축 회전 투영(Rotated Projection)** 적용 필요 |

## 3. 지사 전환 시 핵심 기술 이슈 및 해결 방안

### 이슈 A. 남↔북 방향 노선(경부·중부내륙·서해안·중앙선)의 지도 비율 문제
- **문제**: 광주대구선은 서→동(`가로 폭 1.2° × 세로 폭 0.4°`)으로 뻗어 있어 `1600×700` 와이드 TV 지도와 `540×242` 미니맵에 바로 투영되지만, 남↔북 노선(예: 중부내륙선 김천~충주)을 일반 위경도(`북쪽=위`)로 그리면 화면 중앙에 좁은 세로줄만 생기고 좌우 70%가 빈 공간이 됩니다.
- **해결책 (`주축 회전 투영 + 방위표 표기`)**:
  - 기점 `(lon1, lat1)` → 종점 `(lon2, lat2)` 벡터가 항상 화면 **좌측 하단 → 우측 상단(또는 좌→우 수평)**을 향하도록 회전 각도 $\theta$를 적용해 시·군 경계 폴리곤과 노선 좌표를 함께 변환하고, 지도 우측 상단에 회전된 나침반 아이콘(`🧭 N ↖`)을 표시하면 **전국 어떤 방향의 고속도로든 동일한 50인치 TV 와이드 레이아웃(`2·2·1·2` 관측소 도킹 바)을 100% 재사용**할 수 있습니다.

### 이슈 B. 관측소 콜아웃 카드(`dock`) 및 단기예보 배지(`dx, dy`) 라벨 겹침
- **문제**: 수동으로 `dx, dy` 픽셀 오프셋을 조정하면 지사 추가 때마다 수 시간이 소요됩니다.
- **해결책 (`자동 레이아웃 빌드 스크립트`)**:
  - 관측소 카드(6~8개)는 이정(`km`) 순서대로 상단 도킹 슬롯(`y=110`)과 하단 도킹 슬롯(`y=638`)에 교차 자동 배치하고, 읍·면·동 예보 배지는 노선 폴리라인·IC 라벨과의 최소 이격거리(`>= 14px`)를 만족하도록 **반발력 시뮬레이션(Force-directed label placement) 빌드 스크립트**로 1회 계산해 JSON에 고정하면 수작업 없이 무충돌 지도를 생성할 수 있습니다.

### 이슈 C. 복수 노선 관할 지사 (예: 본선 + 지선 동시 관할)
- **문제**: 일부 지사는 고속국도 2개 노선(예: 본선 `50km` + 지선 `20km`)을 함께 관할하므로 단일 `ROAD_LINE_CODE`나 단일 `roadNum`만으로는 한쪽 노선이 누락됩니다.
- **해결책**: 지사 설정 스키마에서 처음부터 `routes: [{ roadNo: "012", kmaVar: "14", startKm: 95.0, endKm: 176.0 }, ...]` 배열 형태로 정의하여 백엔드가 관할 노선들의 `road_stn_obs`·`road_file_down`·`RWIS`를 병합 반환하도록 설계합니다.

### 이슈 D. 구간 개수 변화에 따른 50인치 TV 무스크롤 레이아웃 대응
- **문제**: 고령지사는 콘존이 정확히 `8개`여서 우측 패널 `8행` 및 격상 팝업 `4×2`에 딱 맞지만, 타 지사는 콘존이 `5~6개`이거나 `10~12개`일 수 있습니다.
- **해결책**:
  - `rwis.css`의 구간 카드 높이를 `--zone-count` CSS 변수 기반 `flex: 1 1 0` 균등 분할로 처리하고(10개 이상일 때는 컴팩트 2열 모드 자동 전환),
  - `ice-alert-modal.js` 상단 노선 현황바는 `grid-template-columns: repeat(var(--branch-zone-count), minmax(0, 1fr))`로 이미 유동 대응이 가능하도록 설계되어 있습니다.

## 4. 권장 아키텍처: 코드 포크(Fork) 대신 `Branch Profile Pack` 설정 분리

지사마다 저장소를 복사(Fork)하면 기상청 API 코드 변경이나 UI 버그 수정 때마다 모든 지사 저장소를 수동 패치해야 하므로 유지보수 비용이 급증합니다. 따라서 **단일 코드베이스 + 지사별 선언형 프로파일 JSON** 구조를 권장합니다.

```
config/
  branches/
    goryeong.json       # 고령지사 (12호선 광주대구선 95.0~176.0k) — 기본값
    namwon.json         # 예: 남원/전주권 지사 프로파일
    daegwallyeong.json  # 예: 대관령/강릉권 지사 프로파일
scripts/
  build-branch-pack.mjs # 통계청 GeoJSON + 노선 KML + ITS/KMA 목록 → 지사별 지도·마스터 자동 생성기
```

### 단계별 전환 실행 순서 (타 지사 적용 시 표준 SOP)
1. **Step 1 (기초 코드 수집 · 반나절)**: 대상 지사의 관할 노선·이정표를 기준으로 KMA `road_stn_obs`(`var` 코드·관측소 ID), RWIS 콘존 ID 목록, ITS CCTV 목록을 스크립트로 자동 덤프합니다.
2. **Step 2 (예보 읍·면·동 및 특보 8개소 확정 · 1~2시간)**: 노선 통과 읍·면·동(고유 격자 12개 내외)과 세부 특보구역(산지/평지 등 CAP 폴리곤 매칭 확인) + 상류 선행감시 1~2곳을 선정합니다.
3. **Step 3 (지도·마스터 자동 빌드 · 1시간)**: 통계청 행정경계 GeoJSON과 고속도로 중심선 좌표를 `build-branch-pack.mjs`에 넣어 주축 회전된 `RWIS_ROUTE_GEO`, 미니맵 폴리라인, 무충돌 라벨 좌표를 생성합니다.
4. **Step 4 (단위 테스트 및 50인치 TV/모바일 검수 · 1시간)**: 불변식(`total1km` 합계, `SFS` 노면코드, `1920×1080` 무스크롤, 모바일 전체화면 지도, 08·18시 브리핑 PNG) 자동 검증 후 배포합니다.
